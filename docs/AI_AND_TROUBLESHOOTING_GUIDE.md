# AI 활용 및 트러블슈팅 기록 가이드 (AI_AND_TROUBLESHOOTING_GUIDE)

본 문서는 프로젝트 핵심 평가 항목인 **기술력(AI 활용 과정 및 Skill 등 AI 표준 기술 적용)**과 **도전과 해결(문제 해결 과정 및 AI 오답 교정 사례)**을 팀 **undefined**가 체계적으로 실천하고 기록하기 위한 가이드입니다.

---

## 1. AI 도구 및 표준 기술(`ios-simulator-skill`) 활용 원칙

### 1.1 AI 활용 기본 원칙
1. **이해 없는 복붙 금지**: AI가 생성한 SwiftUI 및 Node.js 코드는 작성자가 동작 원리와 엣지 케이스를 완전히 이해하고 검증한 뒤에만 커밋합니다.
2. **규칙 문서 기반 지시**: AI에게 작업을 요청할 때 `AGENTS.md`, `docs/CODE_CONVENTION.md`, `docs/PROJECT_CHARTER.md`를 기준으로 삼게 하여 도메인 정책(`포함 키워드 우선`, `위급재난 예외 사용자 선택 제공` 등)과 `SwiftLint` 규칙을 일관되게 준수합니다.
3. **핵심 로직 테스트 동반**: 키워드 우선순위 판별, 지역 매칭, 다조건 검색 쿼리 등 핵심 비즈니스 로직 작성 시 경계값 단위 테스트를 함께 작성하여 검증합니다.

### 1.2 AI 표준 기술 활용: `ios-simulator-skill`
본 프로젝트에서는 AI 표준 기반 기술인 **`ios-simulator-skill`**을 iOS 개발 및 검증 워크플로우에 활용합니다.

- **주요 활용 목적**:
  - SwiftUI 화면 구현 및 수정 후 에이전트가 직접 iOS Simulator에서 앱을 빌드·실행하여 레이아웃과 화면 전환을 검증
  - 관심 지역 선택, 포함/제외 키워드 등록, 위급재난 예외 토글, 다조건 검색 등 사용자 시나리오의 실제 UI 인터랙션 테스트 자동화
  - PR 첨부 및 발표 자료용 시뮬레이터 화면 확인 효율화

## 3. 도전과 해결 & AI 오답 교정 로그 (필수 기록!)

> **왜 지금 바로 적어야 하나요?**
> 개발 도중 겪은 난관과 **"AI가 틀렸을 때 어떻게 발견하고 바로잡았는지"**는 시간이 지나면 구체적인 에러 메시지와 원인을 잊어버리기 쉽습니다. 문제를 해결한 직후(또는 PR 작성 시) 아래 템플릿으로 즉시 남깁니다.

### 기록 템플릿 (복사하여 하단에 누적 추가)

```markdown
### [사례 #번호] 문제 제목 (YYYY-MM-DD, 관련 이슈/PR: #이슈번호)

1. **상황 및 마주친 문제**
   - 어떤 기능을 개발하던 중 어떤 문제(버그, 데이터 포맷 불일치, API 응답 지연, 레이아웃 이슈 등)가 발생했는가?

2. **AI의 초기 제안과 틀렸던 지점 (AI 오답 사례인 경우 필수 작성)**
   - AI가 처음 제시한 코드나 해결책은 무엇이었는가?
   - 왜 틀렸거나 DisasterAlert 정책에 맞지 않았는가?
     *(예: 재난안전데이터 공유 플랫폼 응답 필드명을 실제 스펙과 다르게 가정함, 포함 키워드와 제외 키워드 동시 매칭 시 제외를 우선 처리하여 정책과 반대로 동작함, SwiftLint 규칙에 위배되는 강제 언래핑 코드를 생성함 등)*

3. **원인 분석 및 해결 과정**
   - 어떤 검증(공식 API 응답 대조, 단위 테스트, SwiftLint 검사, ios-simulator-skill 실행 확인 등)을 통해 원인을 파악했는가?
   - 최종적으로 어떻게 문제를 바로잡았는가?

4. **검증 결과 및 배운 점**
   - 재발 방지를 위해 추가한 테스트 케이스나 규칙은 무엇인가?
```

## 4. 누적 트러블슈팅 로그

### [사례 #1] `code.go.kr` 법정동코드 파싱 시 세종특별자치시(`3611000000`) 누락 교정 (2026-11-26)

1. **상황 및 마주친 문제**
   - 설정 화면의 `시·도 → 시·군·구 → 읍·면·동` 알림지역 선택 기능을 위해 행정표준코드관리시스템(`code.go.kr`) 법정동코드 전체자료를 수집·정제하던 중, 시·도 개수가 예상(16개, 전남광주통합특별시 반영 기준)보다 1개 적은 15개로 생성됨.

2. **AI의 초기 제안과 틀렸던 지점**
   - 초기 파서 스크립트에서 10자리 법정동코드 중 뒤 8자리가 `00000000`인 행(`code[2:] == "00000000"`)만 광역 시·도로 분류함.
   - 그러나 **세종특별자치시**는 광역과 기초가 통합된 단층제 행정구역이어서 `3600000000` 코드가 존재하지 않고 `3611000000`으로만 등록되어 있어 시·도 목록에서 누락됨.

3. **원인 분석 및 해결 과정**
   - 생성된 `Regions.json`의 시·도 목록을 출력해 대조한 결과 `3611000000 세종특별자치시`가 빠진 것을 확인함.
   - 파서에 단층제 코드(`3611000000`) 분기 처리를 추가하여 `세종특별자치시 → 세종시 → 조치원읍/다정동 등` 3단계 선택 흐름이 다른 시·도와 동일하게 동작하도록 수정함(최종 16개 시·도, 256개 시·군·구, 5,067개 읍·면·동 반영).

4. **검증 결과 및 배운 점**
   - 재발 방지를 위해 `AlertFilterServiceTests`에 `testBundledRegionCatalogLoadsAllProvincesIncludingSejong()` 단위 테스트를 추가하여 번들 JSON 내 `세종특별자치시` 포함 여부를 자동 검증함.
